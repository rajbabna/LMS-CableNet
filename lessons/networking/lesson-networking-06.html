MOD 06

Module 6: Troubleshooting Methodology & Tools

Theme: Systematic Problem-Solving

Learning Objectives

  • Apply a structured troubleshooting framework to network problems
  • Use core diagnostic tools: ping, tracert, ipconfig, nslookup, netstat
  • Interpret the output of each tool to isolate a problem

Routing Homework Discussion (8:30–9:00)

Review last week's static route diagrams before moving into new material.

Lecture Notes (9:00–10:30)

  1. Gather information (distinguish symptoms from root causes)
  2. Form and test a hypothesis
  3. Isolate the problem (often layer by layer, OSI-style)
  4. Implement a solution
  5. Verify the fix actually worked
  6. Document findings
ToolWhat It Checks
PingLayer 3 IP connectivity to a target
Tracert / TracerouteThe routing path packets take, hop by hop
Ipconfig / IfconfigLocal device's IP, gateway, DNS configuration
NslookupDNS resolution — what IP a name resolves to
NetstatActive network connections on a device
ArpThe IP-to-MAC table on this device
Pathping (Win)Traceroute + per-hop packet-loss stats

Ping yourself, then your IP, then your gateway, then a far address — where the ping stops is where the problem lives:

TestFails → meaning
ping 127.0.0.1TCP/IP stack / drivers
ping own IPInterface not up / wrong IP
ping default gatewayLayer 1/2 problem (cable, port, VLAN, DHCP)
ping remote IPRouting / firewall / WAN
ping remote hostname (IP OK)DNS problem

Lab 6A: Hands-On Tools Demo (10:45–11:30)

  • Ping a server and analyze the output
  • Traceroute to a website and interpret each hop
  • Run ipconfig and locate IP, gateway, and DNS server info
  • Run nslookup on google.com and see the IP behind the domain

Lab 6B: Packet Tracer Tools (11:30–12:30 → 1:15–2:15)

  • Use Packet Tracer's built-in Ping and Tracert utilities between devices
  • Analyze the results and discuss what each tool would tell you

"A user says: I can't reach Google." Walk through the systematic approach:

  1. Ping the gateway
  2. Ping the DNS server
  3. Run nslookup
  4. Narrow down where in the chain the failure is

Wrap-Up (2:15–2:30)

Troubleshooting is a skill built through repetition. Next week: real broken networks to diagnose and fix.

Check for Understanding

  1. What's the first thing to check when a user can't reach a website?
  2. What does traceroute show that ping doesn't?
  3. Walk through the 6-step troubleshooting framework from memory.

Home Assignment

  • Ping 3 websites and save the output
  • Traceroute to youtube.com and analyze the hops
  • Write: "What did each command tell you?"
